# Window pricing: client coverage and correctness boundaries

This matrix describes the local feature on the actually consumed fork baseline `ab1067f3` (token-monitor's pinned tokscale), reviewed after rebasing the experimental implementation. It is scoped to **model reports with date filters and unchanged warm cache hits**. token-monitor itself is unchanged; no remote push or release is authorized until the maintainer responds. Other report entry points and cold/changed-source paths retain their existing behavior.

Coverage is exhaustive for the `define_clients!` registry in `crates/tokscale-core/src/clients.rs`, plus Synthetic routing. The inventory can be checked with `rg -n '^    [A-Za-z].*= [0-9]+ =>' crates/tokscale-core/src/clients.rs`. This document is a snapshot of the reviewed baseline and must be updated if dispatch or reducers change. Function names provide stable evidence across formatting edits; production dispatch and loaders are in `crates/tokscale-core/src/lib.rs`, parser functions are in their corresponding `src/sessions/` modules, and fingerprint helpers are in `src/message_cache.rs`.

The **Static** column records route and downstream-semantics inspection, including post-load mutations. It is not runtime acceptance of the window mechanism. The runtime columns below identify dedicated window fixtures and pristine-baseline CLI comparisons; “Not covered” refers to this feature, not the absence of existing parser tests. Even a covered client may have untested subpaths. Real private histories were not executed for every client.

## Shared contract

- `PricingWindow` contains only borrowed year/since/until predicates and the effective bucket timezone. Its constructor uses the actual caller's `ScannerSettings`; there is no duplicate settings source in deep helpers.
- `refresh_and_price_sieved` refreshes every cached message's derived fields. `PricingWindow::matches` uses the same `date_passes_report_filter` as the final model report. Only an estimated-price call can be skipped; no message, token, identity, model, timestamp, or authoritative cost is discarded.
- Pinned timezones are supported: `UnifiedMessage::date_in_timezone` predicts the same date that `rebucket_date` will assign later, including fallback for nonpositive or unrepresentable timestamps. Prediction does not change date before reducers. Unpinned scans test the refreshed Local-derived date.
- The generic policy loader opts unchanged warm hits into the predicate. Fresh/changed file parsing still uses full pricing. `finalize_codex_messages` is shared by warm/cold/append paths; fallback timestamp correction precedes the optional gate, and headless tagging follows it. Cold and append calls explicitly pass no window.
- `apply_pricing_if_available` protects `CostSource::ProviderReported`, including explicit zero. The unchanged `pricing_multiplier` preserves Zed-hosted markup and OpenAI priority/fast tier behavior. In-window estimates use the current catalog, not a persisted computed estimate.
- Cache entries store raw parser output before pricing; warm output returns no new cache entry. `SourceMessageCache::take` clones retained-history/dirty payloads, and `save_if_dirty` merges raw dirty entries with existing shards. A sequence of narrow, wide, and all-time windows therefore cannot persist skipped prices into another scan.
- `flush_message` preserves its existing order: requested-client filtering, Synthetic gateway normalization, then optional rebucketing. All whole-history dedup and ownership coverage remains available before final report filtering.

## Recovery overlay and remote-backed sources

`recovery::apply` runs after native message flush in the collecting path. Recovered request archives are suppressed by complete native session identities and message signatures, independent of price. `recovery::merge` sums and fills positive gaps strictly by final `(client, date)` groups; it never transfers cost across calendar days. An outside-window skipped native estimate can change only an outside-window recovery floor, which is then excluded by the same final predicate. Inside-window native prices remain complete before recovery. Archive dates are aligned using the same pinned timezone; daily-floor rows keep their date when their synthetic timestamp is reset to zero. Submission continues to use its original pipeline without recovery or this window optimization.

Cursor has `parse_local: false` in the registry but its synced CSV/JSON cache is still read by model reports and uses W. Copilot's OTEL/synced file cache uses W while its other sources stay F. Antigravity's RPC-synced JSONL source uses F alongside its CLI/extension DB surfaces. Local-versus-remote acquisition is distinct from cache/price policy; this feature does not change upstream syncing or acquisition.

New tests in `crates/tokscale-core/src/tests/window_pricing.rs` exercise public `get_model_report` against an independent full-pricing parse/aggregate reference for Codex, Claude, Cursor, OpenCode, Hermes, and OpenClaw, with GJC authoritative zero covered in the missing-catalog sequence. The source includes all grouping modes, independently compared report totals, current catalog replacement, persisted raw-cache byte equality, source append/rewrite/compaction/delete, and SQLite update/insert/delete sequences. Codex tier pricing and fork recovery archive/daily-floor consistency have dedicated fixtures.

`crates/tokscale-core/src/tests/window_dates.rs::window_prediction_matches_final_date_filter_without_mutating_messages` compares effective-date prediction with the real final flush predicate at fixed timestamp/date boundaries. `crates/tokscale-core/src/tests/window_pricing.rs::effective_scan_timezone_controls_window_estimation_at_date_boundaries` verifies that caller scanner settings control the gate even if the options carry a different setting. These are synthetic fixtures with deterministic prices and dates; they provide execution evidence only when the validation report records passing commands. Clients listed only as Static have not acquired new real-data validation merely by appearing in this table. Existing parser/reducer tests remain useful evidence of their unchanged behavior.

## Spec

The requested “保留完整 reducer 语义” is preserved by retaining every cached message through reducer/ownership stages and gating only estimated pricing. The earlier dual-settings/pinned-timezone weakness is resolved by predicting final bucket dates from actual scan settings. Public-report comparisons now include totals and repeated window/catalog sequences, addressing the original incomplete equality evidence. Unoptimized specialized lanes and Grok's final repricing remain explicit performance limitations, rather than unsupported clients or silent data losses. Fork-only recovery and tier behavior were inspected and have dedicated synthetic fixtures. Exhaustive real-history execution and future baseline drift are not claimed; maintenance response still gates remote delivery.

Review summary: no unresolved production findings were reported in either static-review axis. Per-client runtime acceptance remains incomplete; the representative fixture results must not be described as every client passing. Dynamic validation outcomes and performance measurement are separate evidence.
